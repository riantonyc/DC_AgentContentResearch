# 1. PROJECT IDENTITY

## Project Name

**AI-Powered Content Research & Operations Platform**

## Positioning

**Adaptive Agentic AI Platform for Content Creators**

## Primary Role of the Platform

This platform is not merely an AI chatbot. The platform must be
positioned as:

> **Creative Research Partner + Content Intelligence System +
> Operational Assistant**

for content creators.

The system supports creators through the following stages:

IDEA ↓ RESEARCH ↓ UNDERSTAND ↓ DISCOVER ↓ CREATE ↓ PLAN ↓ EXECUTE ↓
ANALYZE ↓ LEARN ↓ IMPROVE

Therefore, this project is an **AI-powered content operating
workspace**, not simply a chat application.

------------------------------------------------------------------------

# 2. PROJECT VISION

The primary vision is to build an AI platform that can become a working
partner for content creators.

Creators should not have to constantly switch between:

-   Google / search engines
-   news websites
-   social media
-   spreadsheets
-   note-taking applications
-   content planning tools
-   AI chatbots
-   analytics tools
-   task management tools

to complete a single piece of work.

The platform aims to unify these processes inside one workspace.

The ultimate goal is:

> The creator provides a goal or problem using natural language. The AI
> Agent understands the context, determines the required workflow, uses
> the available tools, performs research or analysis, produces useful
> output, stores relevant information, and helps the creator continue to
> the next stage of the workflow.

------------------------------------------------------------------------

# 3. CORE PROBLEM

Content creators commonly face the following problems:

### 3.1 Research Is Too Manual

Creators have to:

1.  search for keywords,
2.  open many websites,
3.  read articles,
4.  compare information,
5.  record sources,
6.  search for trends,
7.  find content angles,
8.  and only then start creating content.

This process requires significant time and effort.

------------------------------------------------------------------------

### 3.2 Information Is Scattered

Research, ideas, scripts, tasks, calendars, analytics, and reports are
often stored in different applications.

As a result:

-   context switching is high,
-   information can easily be lost,
-   research has to be repeated,
-   creators must repeatedly explain their context to AI.

------------------------------------------------------------------------

### 3.3 Generic AI Does Not Understand the Creator

Traditional AI usually only knows the information provided within a
particular conversation.

This project aims to create an AI system that can understand creator
context over time.

Example:

Creator: \> "I prefer educational content with storytelling."

AI Memory:

-   preferred language = Indonesian
-   style = educational storytelling
-   audience = young adults
-   preferred format = short video
-   preferred tone = casual

When the creator requests new ideas, the agent can use this relevant
context.

------------------------------------------------------------------------

# 13. MEMORY RULES

The agent must follow these rules:

### DO

-   store relevant information,
-   use memory when it helps the current task,
-   update memory when information changes,
-   distinguish temporary context from long-term preferences.

### DON'T

-   store every conversation,
-   store sensitive information without a legitimate need,
-   use memory when it is irrelevant,
-   assume memory is always correct,
-   mix context between unrelated projects.

# 33. HUMAN-IN-THE-LOOP

The agent must not make important decisions without user confirmation
when an action has meaningful consequences.

### Can usually be automated

-   Research
-   Summarization
-   Idea generation
-   Draft creation
-   Analysis

### Should generally require confirmation

-   Delete content
-   Delete memory
-   Publish content
-   Send external communication
-   Change important settings
-   Execute irreversible actions

Principle:

> **AI helps the creator take action; it does not take control away from
> the creator.**

# 47. MEMORY VS PROJECT CONTEXT

Information that is relatively reusable.

### Project Context

Information specific to the current project.

Examples:

Current objective: Create 20 videos.

### Conversation Context

Temporary information from the current conversation.

Example:

"Use angle number 3."

Not every piece of conversation context should be stored as memory.

-   Findings

Information selected for storage and future reuse.

-   Knowledge
-   Source
-   Context
-   Tags
-   Embedding
